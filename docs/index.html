Memory Safety Checks

Rather than replacing C or C++ pointers with smart-pointer-only dialects or compiler wrapper scripts, Safe-C tracks allocation states across the control-flow graph inside the compiler and halts builds when a violation is provable.

Violation Diagnostic Tag What Is Caught Disable Flag
Memory leak [-Wsafec-leak] Heap allocation leaves scope, returns, or is overwritten without being freed or escaped -DSAFE_C_NO_LEAKS
Double free [-Wsafec-double-free] Calling free, delete, or delete[] on an already freed pointer -DSAFE_C_NO_DOUBLE_FREE
Use-after-free [-Wsafec-use-after-free] Dereferencing (*p, p->m, p[i]) after deallocation -DSAFE_C_NO_UAF
Modified base free / loss [-Wsafec-modified-base] Freeing a non-zero interior offset, or shifting a pointer when no alias retains offset 0 -DSAFE_C_NO_ARITHMETIC
Allocator mismatch [-Wsafec-mismatched-dealloc] Mixing malloc/free, new/delete, and new[]/delete[] -DSAFE_C_NO_MISMATCH
Non-heap free [-Wsafec-invalid-free] Passing a stack or non-heap address to a heap deallocator -DSAFE_C_NO_MISMATCH
Out-of-bounds access [-Wsafec-bounds] Constant negative (p[-1]) or out-of-range indexing/dereference beyond known allocation size -DSAFE_C_NO_BOUNDS
Null dereference [-Wsafec-null-deref] Dereferencing a pointer known to hold NULL or nullptr on that path -DSAFE_C_NO_NULL
Uninitialized dereference [-Wsafec-uninitialized] Dereferencing a local pointer before any assignment -DSAFE_C_NO_UNINIT
Dangling stack return [-Wsafec-return-local-addr] Returning the address of a function-local stack variable -DSAFE_C_NO_DANGLING
Iterator & data handle invalidation [-Wsafec-iterator-invalidation] Mutating an STL container (e.g. push_back, insert, erase) while iterating or using an old .data() / .c_str() handle -DSAFE_C_NO_ITERATOR

Edge Cases & Zero-False-Positive Rules

Allowed Idioms (Compiles Cleanly)
  • Returned allocations: allocating in a helper function and returning the pointer to the caller.
  • Ownership transfer: assigning a local allocation into an outer pointer, parameter slot, or struct field.
  • Safe STL & RAII: it = v.erase(it) refresh, mutating immediately before break/return, indexed loops, and placement new.
  • Pointer arithmetic with backup: advancing a cursor or shifting a base pointer while another variable keeps offset 0.
  • Safe no-ops & guarded branches: free(NULL), delete nullptr, realloc() re-assignment, and dereferences guarded by if (p).
Rejected Idioms (Halts Compilation)
  • Lost base address: modifying the only variable holding an allocation base (p += 4; free(p);).
  • Branch & overwrite leaks: leaking on an early return path, overwriting an unfreed pointer, or double-free/double-delete.
  • Iterator / buffer invalidation: calling push_back() inside a range-for loop or dereferencing stale .data() pointers after container growth.
  • Known OOB / negative / null reads & writes: negative indexing (p[-1]), constant index overflow, and unguarded null paths.
/* Allowed: cursor moves while 'base' retains offset 0 */
void process_buffer(void) {
    char *base = (char *)malloc(64);
    char *cursor = base;
    cursor += 8;
    free(base);
}

/* Rejected: base address is lost before free() */
void invalid_buffer(void) {
    char *buf = (char *)malloc(32);
    buf += 4;
    free(buf);
}

How Safe-C Differs from Rust & Other Languages

Safe-C is an extension inside an existing C/C++ compiler rather than a separate language, borrow-checked syntax, or garbage-collected VM. It trades Rust's whole-program soundness proofs for zero-rewrite compatibility with standard C and C++.

Aspect Safe-C (GCC / G++ Plugin) Rust Go / Java / C# Sanitizers (ASan / UBSan)
Language & ABI Standard C11/C17 & C++20; keeps existing C/C++ ABI intact Requires rewriting in Rust or wrapping C APIs in unsafe blocks Different language + managed VM / FFI marshalling boundary Standard C/C++ via compiler instrumentation flags
Aliasing & pointers Allows multiple aliasing raw pointers & arithmetic when base offset 0 is retained Enforces strict single mutable borrow (&mut T) & explicit lifetime annotations No arbitrary raw pointer arithmetic in safe code Allows all pointers; faults when invalid memory is touched at runtime
When errors are caught At compile time (GIMPLE CFG pass + analyzer) At compile time (borrow checker & type system) Mostly at runtime (null/bounds panics & GC) At runtime (only on code paths reached by tests)
Runtime overhead Zero by default (optional libsafe_c_rt if linked) Zero runtime overhead for borrow checks Tracing GC pauses & runtime allocation metadata ~2x CPU slowdown + shadow memory usage
Incremental adoption Enable/disable per file (-DSAFE_C_DISABLE) or warn-only (-DSAFE_C_WARN_ONLY) Borrow checker applies uniformly to all non-unsafe Rust code Requires runtime ecosystem adoption Per-build compiler & linker flag
Where Safe-C Fits Best

Existing C and C++ codebases where rewriting into Rust is impractical, ABI compatibility matters, and teams want immediate compile-time guardrails on leaks, UAF, OOB, modified-base frees, and STL invalidation.

Honest Scope vs. Rust

Unlike Rust—which mathematically guarantees memory and thread safety in all safe code—Safe-C analyzes intraprocedural GCC CFG paths and does not prove absence of multithreaded data races or arbitrary runtime-computed aliasing.

How It Works

Safe-C separates shared state analysis from toolchain integration so both Linux and Windows builds enforce the same lifetime rules:

Component Artifact Role
Linux GCC plugin safe_c.so Runs a Reverse-Post-Order (RPO) GIMPLE CFG pass inside cc1/cc1plus after SSA construction, merging predecessor states at GIMPLE_PHI nodes.
GCC toolchain specs src/specs/safe_c.specs Loads -fplugin=safe_c automatically unless disabled and translates -DSAFE_C_* defines into plugin arguments.
Windows MinGW-w64 addon safe_c.dll Works via GCC plugin mode or direct cc1.exe/cc1plus.exe import hook via windows_addon.cpp when MinGW builds without plugin support.
Core static analyzer libsafe_c_core.a Shared typestate table, path canonicalizer, source snippet highlighter, and Windows/standalone analyzer pass.
Runtime guardrails libsafe_c_rt.so / .a / .dll Optional dynamic tracking for opaque external allocations; uses immortal singletons so Safe-C can compile itself safely.

Building & Installing Into Your Compiler

1. Build From Source & Run Tests

git clone https://github.com/Kush-Kelaiya22/Safe-C.git
cd Safe-C
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build --output-on-failure

2. Install Into Linux GCC Compiler Settings

For non-invasive use that never affects system package builds (such as makepkg, DKMS modules, or GCC updates), keep system GCC untouched and pass -specs= per project or shell alias: 

alias sgcc='gcc -specs=/path/to/Safe-C/src/specs/safe_c.specs -fplugin=/path/to/Safe-C/build/lib/safe_c.so'
alias sg++='g++ -specs=/path/to/Safe-C/src/specs/safe_c.specs -fplugin=/path/to/Safe-C/build/lib/safe_c.so'

To enable Safe-C globally on Linux GCC, run the integration script (or copy safe_c.so into GCC's plugin folder and merge *self_spec: into gcc -dumpspecs so *libgcc: and --eh-frame-hdr stay intact for C++ linking and unwinding): 

sudo python3 tools/integrate_toolchain.py

# Or manually copy + merge specs:
sudo cp build/lib/safe_c.so "$(gcc -print-file-name=plugin)/safe_c.so"
SPECS_PATH="$(dirname "$(gcc -print-libgcc-file-name)")/specs"
sudo rm -f "$SPECS_PATH"
python3 -c '
import subprocess
raw = subprocess.check_output(["gcc", "-dumpspecs"]).decode()
rule = next(l for l in open("src/specs/safe_c.specs").read().splitlines()
            if l.strip() and not l.startswith("#") and not l.startswith("*"))
clean_rule = rule[2:] if rule.startswith("+ ") else rule
i = raw.find("*self_spec:")
j = raw.find("\n*cc1_cpu:", i)
print(raw[:i] + "*self_spec:\n" + clean_rule + "\n" + raw[j:], end="")
' | sudo tee "$SPECS_PATH" > /dev/null

# Optional runtime guardrail libraries:
sudo cp build/lib/libsafe_c_rt.so build/lib/libsafe_c_rt.a /usr/local/lib/
sudo ldconfig
System package safety: Do not overwrite GCC's specs folder with bare safe_c.specs alone, or g++ will drop libgcc_s and --eh-frame-hdr. If global specs are enabled, export SAFE_C_DISABLE=1 when building third-party packages, and remove "$SPECS_PATH" before or after distro GCC version upgrades.

3. Install Into Windows (MinGW-w64)

python tools/integrate_toolchain.py
# Or target a specific MinGW-w64 compiler:
python tools/integrate_toolchain.py C:\msys64\ucrt64\bin\gcc.exe
# Remove integration anytime:
python tools/integrate_toolchain.py --uninstall

Compiler & Plugin Flags

If Safe-C is disabled globally in a build script or environment, you can force it back on per file, downgrade errors to warnings, or disable individual checks without modifying the specs file.

Preprocessor Flag (with specs) Direct Plugin Argument Effect
-DSAFE_C_ENABLE -fplugin-arg-safe_c-enable Force-enable Safe-C even if -DSAFE_C_DISABLE or SAFE_C_DISABLE=1 is set.
-DSAFE_C_DISABLE -fplugin-arg-safe_c-disable Skip Safe-C checks for that compilation unit (env: SAFE_C_DISABLE=1).
-DSAFE_C_WARN_ONLY -fplugin-arg-safe_c-mode=warn Emit warnings instead of halting compilation (env: SAFE_C_MODE=warn).
-DSAFE_C_FATAL -fplugin-arg-safe_c-mode=fatal Treat memory safety diagnostics as fatal errors (default).
-DSAFE_C_NO_LEAKS -fplugin-arg-safe_c-leaks=off Disable leak diagnostics while keeping other checks active.
-DSAFE_C_NO_DOUBLE_FREE -fplugin-arg-safe_c-double-free=off Disable double-free diagnostics.
-DSAFE_C_NO_UAF -fplugin-arg-safe_c-uaf=off Disable use-after-free diagnostics.
-DSAFE_C_NO_BOUNDS -fplugin-arg-safe_c-bounds=off Disable static out-of-bounds checks.
-DSAFE_C_NO_NULL -fplugin-arg-safe_c-null=off Disable null dereference checks.
-DSAFE_C_NO_UNINIT -fplugin-arg-safe_c-uninit=off Disable uninitialized pointer checks.
-DSAFE_C_NO_MISMATCH -fplugin-arg-safe_c-mismatch=off Disable allocator/deallocator mismatch and non-heap free checks.
-DSAFE_C_NO_DANGLING -fplugin-arg-safe_c-dangling=off Disable local stack-address return checks.
-DSAFE_C_NO_ARITHMETIC -fplugin-arg-safe_c-arithmetic=off Disable modified-base pointer arithmetic checks.
-DSAFE_C_NO_ITERATOR -fplugin-arg-safe_c-iterator=off Disable C++ STL iterator and .data()/.c_str() invalidation checks.

Diagnostics Format

Diagnostics follow GNU/GCC formatting conventions: lowercase message text, %qs-quoted identifiers, no trailing punctuation on the primary message, category tags ([-Wsafec-*]), line gutters with caret underlines, and secondary note: locations pointing to the original allocation or prior free. 

tests/compile_fail/double_free.c:6:5: error: double free of 'ptr' [-Wsafec-double-free]
    6 |     free(ptr);
      |     ^~~~~~~~~
tests/compile_fail/double_free.c:5:5: note: previously deallocated here
    5 |     free(ptr);
      |     ^~~~~~~~~

tests/compile_fail/altered_pointer_free.c:6:5: error: attempt to free interior pointer 'buf' at offset 4 bytes [-Wsafec-modified-base]
    6 |     free(buf);
      |     ^~~~~~~~~
tests/compile_fail/altered_pointer_free.c:4:24: note: original allocation base created here
    4 |     char* buf = (char*)malloc(32);
      |                        ^~~~~~~~~~
