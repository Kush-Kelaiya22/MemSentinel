Safe-C: Native Memory Safety Extension for GCC & G++

Safe-C is a compile-time memory safety plugin and toolchain addon for GNU GCC and G++. It statically tracks heap allocations and pointer bindings, halting compilation directly upon detecting invalid deallocations, use-after-free, lost base addresses, or unescaped leaks.

GCC >= 4.5.0 C++20 & C11 AGPLv3 Zero Wrapper Scripts Zero Checker Binaries Cross-Platform

1. Overview & Principles

Safe-C does not ban or restrict raw pointers, pointer arithmetic, malloc/free, or C++ new/delete. Rather than substituting the language with an artificial dialect or forced smart pointer wrappers, Safe-C preserves standard idioms while enforcing pointer lifetime invariants.

Architectural Mandate

Safe-C operates without wrapper scripts or standalone memory-checking executables. On Linux and Unix platforms, it executes via GCC's native plugin architecture (-fplugin=safe_c.so). On Windows MinGW-w64 toolchains, it operates as an automatic companion addon library.

4. Pointer Offset Preservation & Arithmetic

Safe-C permits unrestricted pointer arithmetic. A pointer's offset can be modified through ++, --, +=, or -= as long as there is a variable that contains the original base address.

  • Permitted: Creating a cursor or temporary pointer and advancing it across a buffer while retaining the base address in another variable.
  • Permitted: Shifting the original pointer variable when a backup pointer stores the base address, followed by deallocating the base variable.
  • Prohibited: Shifting an only pointer variable when no other variable retains the base address (offset 0). In this scenario, the base address is permanently lost, and compilation is halted.
  • Prohibited: Passing an interior or shifted pointer to free() or delete. 
// Valid Idiom: Cursor offset altered while base is preserved in a variable
void process_buffer(void) {
    char* base = (char*)malloc(64);
    char* cursor = base;
    cursor += 8;
    cursor++;
    free(base); // Base address freed cleanly
}

// Prohibited Idiom: Offset altered with zero variables retaining base address
void invalid_buffer(void) {
    char* buf = (char*)malloc(32);
    buf += 4;  // ERROR: Cannot alter pointer offset: no variable retains original base address
    free(buf);
}

5. Toolchain Setup & Invocations

Zero-Flag Default Activation

Safe-C can be activated by default across your compiler toolchain so that plain gcc and g++ invocations automatically halt on memory hazards without any extra flags: 

# Enable Safe-C by default for all host GCC/G++ compilers
safe_c --enable-default

# Or enable via CMake build target
cmake --build build --target enable-default

# Check default activation status
safe_c --status

# Disable default auto-loading
safe_c --disable-default

Per-Invocation Options

# 1. Universal specs integration (works across ALL MinGW-w64 toolchains)
gcc -specs=build/specs/safe_c.specs -c main.c -o main.o
g++ -specs=build/specs/safe_c.specs -c app.cpp -o app.o

# 2. Direct compiler plugin invocation (for plugin-enabled toolchains)
gcc -fplugin=build/bin/safe_c.dll -c main.c -o main.o

# 3. Direct front-end analysis
safe_c main.c

# 4. Bypassing Safe-C when compiling third-party code
gcc -DSAFE_C_DISABLE -c legacy.c -o legacy.o
set SAFE_C_DISABLE=1

Linux / macOS (GCC Plugin)

gcc -fplugin=build/lib/safe_c.so -c main.c -o main.o

6. Diagnostic Output & GNU/GCC Error Highlighting

When an unsafe operation is detected, Safe-C emits authentic GNU/GCC-styled diagnostics to stderr with gutter line numbers, source code snippets, caret token underlines, and ANSI syntax colorization. Address scope resolution ensures .\x.c, ./x.c, and x.c resolve to identical file identities, and each line is emitted once per violation type:

      |     ^~~~
tests/compile_fail/double_free.c:5:5: note: Previous deallocation occurred here:
    5 |     free(ptr);
      |     ^~~~
compilation terminated due to memory safety violations.

      |         ^~

      |                        ^~~~~~

7. Self-Compilation & Dogfooding

Safe-C is implemented in modern C++20 and C11, strictly dogfooding its own safety model:

  • Zero Invariant Violations: All internal data structures, state tables, and AST caches adhere to Safe-C's typestate rules, ensuring zero memory leaks and zero use-after-free conditions.
  • Self-Hosting Verification: Safe-C can be built with its own plugin enabled (-fplugin=safe_c), passing full static analysis cleanly. 
# Clone and compile Safe-C from source
git clone https://github.com/Kush-Kelaiya22/Safe-C.git
cd Safe-C

# Configure and compile with Ninja or Make
cmake -B build -G "Ninja" -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release

8. Binary Migration & Project Adoption

Safe-C provides a non-breaking, incremental path for introducing compile-time memory safety into existing C and C++ codebases:

  • Zero Code Refactoring: No forced migration to smart pointers or dialect subsets. Standard T* pointers, pointer arithmetic (ptr++, ptr += n), malloc/free, and new/delete are preserved.
  • Audit Phase (-fplugin-arg-safe_c-mode=warn): Audit legacy codebases by emitting warnings without halting production builds.
  • Enforcement Phase (Default): Terminate compilation with exit code 1 whenever new memory safety hazards are introduced.
  • Selective Exemption: Exempt unmodified third-party vendor directories via -DSAFE_C_DISABLE or export SAFE_C_DISABLE=1.
  • Runtime Transition Defense: Link libsafe_c_rt to capture dynamic allocations across opaque library boundaries into safe_c_runtime.log.

9. Testing Suite Architecture

Safe-C includes an automated verification test matrix covering all compile-time and runtime guarantees:

Test Category Target Function Coverage Objective
Compile-Fail Suite test_compile_fail_cases() Verifies that Double Free, Use-After-Free, Altered Base Deallocation, and Leaks halt compilation with non-zero exit codes.
Compile-Pass Regression Suite test_compile_pass_cases() Ensures idiomatic raw pointers, cursor arithmetic, and C++ RAII lifetimes compile with zero false positives.
Pointer Offset & Invariant Suite test_pointer_offset_invariants() Validates that cursor offset alteration is allowed when a base variable exists, and rejected when base is lost.
Address Scope Resolution Suite test_address_scope_resolution() Confirms .\x.c, ./x.c, and x.c resolve to identical physical paths with single-line diagnostic deduplication.
Lexical Block Scoping Suite test_lexical_block_scope_resolution() Ensures compound statement blocks ({ ... }) correctly isolate lifetimes and catch unescaped leaks at scope exit.
Diagnostic Formatting Suite test_gnu_gcc_diagnostic_highlighting() Validates line gutters, carets, underline tildes, ANSI colorization, and color toggle flags.
Runtime Guardrails Suite test_runtime_guardrails() Verifies runtime heap tracking, forensic logging, and memory leak summary emission.
