Safe_C++: Native Memory Safety Plugin for GCC / G++

Safe_C++ is a native compile-time memory safety plugin and addon for GNU GCC and G++. It statically verifies memory operations directly within the compiler toolchain, enforcing pointer safety invariants and immediately terminating compilation when unsafe operations are detected.

Architecture: Pure Plugin / Addon Zero Wrapper Executables GCC >= 4.5.0 Compatible Language: C++20 / C11 License: AGPL-3.0

1. Static Safety Guarantees

Safe_C++ does not ban or restrict raw pointers, pointer arithmetic, malloc/free, or C++ new/delete. Instead, it mathematically models the lifecycle of each pointer binding and underlying allocation cell. The compiler halts immediately on any of the following violations:

Violation Class Trigger Condition Compiler Action
Double Free Invocation of free(), delete, or delete[] on an already deallocated pointer cell. Fatal compile error; compilation halts immediately.
Use-After-Free Pointer dereference (*ptr, ptr->field, ptr[i]) after associated cell deallocation. Fatal compile error; compilation halts immediately.
Altered Base Free Attempting to deallocate a pointer whose address has been shifted via pointer arithmetic (interior pointer free). Fatal compile error with exact shifted byte offset.
Memory Leak Dynamically allocated pointer cells that do not escape and are not deallocated before function/scope exit. Fatal compile error; identifies original allocation site.

2. Typestate Transition Automaton

Every pointer symbol is tracked through a deterministic finite-state automaton that associates each pointer binding with its canonical heap allocation cell.

+-----------------------------------------------------------+ | | [UNALLOCATED] ---- malloc() / new ----> [ALLOCATED] | | | ptr += offset | v | [INTERIOR_OFFSET] | | | free(ptr) | | | v | {FATAL: MODIFIED_BASE_FREE} | | [ALLOCATED] ---- free() / delete ----> [FREED] | | | +------------+-----------+ | | | | free(ptr) *ptr | | | | v v | {FATAL: DOUBLE_FREE} {FATAL: USE_AFTER_FREE} | [ALLOCATED] ---- scope exit without free ----> {FATAL: MEMORY_LEAK}

3. Dual-Mode Plugin Architecture

Safe_C++ operates without wrapper scripts or standalone memory-checking executables. It integrates directly into standard compiler distributions across multiple operating systems:

Target Environment Integration Mode Artifact Produced Loading Mechanism
Linux (glibc / musl) Native GCC Plugin Pass safe_cpp.so Pass manager callback registered via PLUGIN_PASS_MANAGER_SETUP.
Windows (MinGW-w64) Native Compiler Addon libwinpthread-1.dll Automatically loaded by cc1.exe and cc1plus.exe via PE link resolution.
Cross-Platform Runtime Dynamic & Static Ledger libsafe_cpp_rt.a / .dll Tracks opaque external allocations; writes diagnostics to safe_cpp_runtime.log.

4. Toolchain Configuration & Usage

Once the plugin or addon is placed in the toolchain directory, invocation of standard compiler commands automatically executes the checks: 

# Standard compile command (Safe_C++ runs automatically)
gcc -c module.c -o module.o
g++ -c app.cpp -o app.o

# Bypassing Safe_C++ when compiling trusted legacy third-party source
gcc -DSAFE_CPP_DISABLE -c legacy.c -o legacy.o

# Alternatively via environment variable
set SAFE_CPP_DISABLE=1
gcc -c legacy.c -o legacy.o

5. Compiler Diagnostic Output

When an unsafe operation is detected, Safe_C++ emits standard GCC-compatible diagnostics to stderr and terminates compilation:

Example A: Double Free Detection

tests/compile_fail/double_free.c:6:5: error: [Safe_C++] Double free detected on pointer 'ptr'. tests/compile_fail/double_free.c:5:5: note: Previous deallocation occurred here: compilation terminated due to memory safety violations.

Example B: Altered Base Deallocation

tests/compile_fail/altered_pointer_free.c:6:5: error: [Safe_C++] Attempt to free altered/interior pointer 'buf'. Address was shifted by 4 bytes before deallocation. tests/compile_fail/altered_pointer_free.c:4:24: note: Original allocation base was created here: compilation terminated due to memory safety violations.

Example C: Use-After-Free Detection

tests/compile_fail/use_after_free.cpp:4:5: error: [Safe_C++] Use-After-Free: Pointer 'data' dereferenced after deallocation. tests/compile_fail/use_after_free.cpp:3:5: note: Pointer was deallocated here: compilation terminated due to memory safety violations.
